# Milan Horses CRM - Open Design Brief

## Source Systems

- **Application + Dashboard:** operational SaaS base for dense CRM screens, metrics, filters and tables.
- **Linear App:** precise dark operational language for queue/radar surfaces where speed matters.
- **Resend + Superhuman:** premium messaging/editor direction for email and WhatsApp creation.
- **Atelier Zero + Luxury:** editorial restraint, warm paper, hairline rules and luxury auction tone.
- **Mission Control:** real-time auction radar, status, telemetry and action lanes.

## Product Rules

- This is an internal CRM, not a landing page.
- The core job is to act: sync, segment, message, follow up, and assemble auction intelligence.
- Contacts/client CRM must remain separate from Studbook/horse database.
- A non-technical user must be able to create premium campaigns from templates and blocks.
- Do not use decorative blobs, default indigo, fake hero gradients, emoji icons, generic feature copy or invented SaaS claims.
- Use one dominant entry point per screen and at most one accent family per direction.

## Visual Direction

- **CRM Core:** light, editorial-operational. Warm ivory canvas, navy ink, bronze accent, dense but calm.
- **Estudio:** premium email workshop. Dark gallery preview, warm cream editor, image/banner blocks, quality rail.
- **Radar VIP:** native dark command center. Amber/gold auction values, cyan active state, action lanes.
- **Studbook:** archive/research room. Warm paper, catalog typography, pedigree panels and secondary database framing.

## Implementation Translation

- Sidebar becomes quiet and categorical: CRM, Marketing, Leiloes, Inteligencia.
- Tables get saved views, global sorting, right-side detail sheet and quick actions.
- Estudio gets a block library, preview, brand presets, image/banner upload slots and direct campaign handoff.
- Radar VIP gets auction scope, segment lanes, message readiness and follow-up status.
- Studbook gets its own shell and visual identity so it never feels mixed with client CRM.
